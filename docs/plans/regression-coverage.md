# Released-feature regression protection

## Goal
Protect all released 0.3 features before new development, combining existing suites with adversarial, multi-member, and packaged-product regression tests. SPEC.md is the behavioral authority. Coverage means an explicit feature/scenario matrix, not a claim to enumerate all possible inputs.

## Global Constraints
- Preserve released APIs, wire schema v2, owner-derived authorship, append-only persistence, quarantine, and visibility semantics.
- Use isolated temporary data and deterministic fake embeddings; no model downloads, real Drive credentials, real home edits, or package publication.
- Exercise real repositories/services/import-export and real CLI subprocesses where practical. Mock external boundaries and injected failures, not the behavior under test.
- Assert outcomes and invariants, not implementation call counts alone. Use bounded deterministic schedules/seeds, no timing sleeps, and clean up resources.
- Do not weaken tests or encode a discovered bug as expected behavior. Report genuine defects with a reproduction before minimal production fixes.
- Keep dependency versions and release versions unchanged. Run PostgreSQL cases in CI; clearly distinguish local SQLite evidence from PostgreSQL evidence.

## Task 1: Backend regression scenarios
Read SPEC.md and inventory existing backend coverage. Add focused test modules under app/tests covering remaining gaps: three independent members with real databases and services; bidirectional/offline catch-up/repeated and reordered delivery; update/delete before originals; restart persistence and owner recovery; roster exclusion, forged authors, cross-author links; conflicting UUIDs and duplicate deliveries; interrupted/truncated/malformed batches and atomic retry; injected publication/database failures and retry without lost data. Exercise visible results through semantic/keyword/hybrid search, recent/history/summary/context, with filters and exact source IDs. Add deterministic generated operation/delivery cases if useful with independent expected state. Run core multi-member scenarios on SQLite and PostgreSQL with isolated backend state and CI's existing integration marker; do not silently share node state or erase unrelated schemas. Extend actual MCP dispatcher regression cases for all tools/invalid argument shapes where existing coverage lacks it. Cover sync health/aggregate counters throughout failure/recovery. Prioritize meaningful cross-feature oracles over redundant unit tests. Produce a backend coverage inventory and honest remaining boundaries in the task report. Run Python unit suite, Ruff and strict mypy before commit.

## Task 2: CLI and distributed package regression
Read existing CLI tests and production command surface. Add uncovered adversarial parser/configuration/editor/guard/lifecycle/sync cases with pure helpers or isolated HOME and external-boundary fakes. Build and pack the actual npm artifact, extract/install into a temporary consumer directory and execute its shipped CLI in subprocesses; verify version/help/command registration, bundled runtime/templates/fixture/version coupling, exclusion of secrets/caches/tests, and read-only sync success/degraded/malformed/truncated/oversized/unreachable cases using a local HTTP server. No real Docker/Nix/rclone mutations or authenticated registry access. Add a reusable package smoke script/test command suitable for CI using only existing dependencies, with finite process timeouts and cleanup. Prove no source-checkout-only import dependency. Run CLI lint/types/tests/build and smoke before commit. Document cases and remaining platform boundaries in report.

## Task 3: CI gates and feature matrix
Add docs/regression-testing.md mapping every public feature/command family and invariants to existing/new test modules and layers, supported failure cases, exact commands, and explicit gaps (real Drive propagation, OS integration and real model quality). Add CI package-smoke gate and make regression target covering normal checks plus packaged smoke; existing PostgreSQL integration must collect the new multi-member scenarios. Keep existing macOS Nix/release gates intact and require new gate before publication. Run full check, evaluator and packaged smoke; inspect integration collection. Add meaningful mutation/sensitivity probes for key new invariants when practical and document observed red/green evidence without committing mutants. Prepare PR, no merge/release.
